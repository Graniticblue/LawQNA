# 웰컴 화면 재설계 — "질의 전 초기 세팅" 온보딩 (v1 · 확정)

> 목적: 첫 화면을 **"바로 질문하는 곳"**에서 **"질문하기 전에 자료를 갖추는 곳"**으로 재구성.
> 사용자가 ①자료를 검색하고 → ②첨부하고 → ③추가 설정을 한 뒤에 질문을 던지는
> **1st → 2nd → 3rd 프로세스**를 화면 가운데에 명시적으로 제시한다.
> 단, **전부 선택 사항**이며 익숙해진 사용자는 안내 없이 바로 질문한다.

---

## 1. 문제의식 (현재)

- 현재 웰컴 화면: 로고(가운데) + 예시 카드 6개 + 하단 질문창.
- **문제 1** — 6개 카드가 "질문 예시"라는 안내가 없어서, 사용자가 그게 예시인지 기능인지 헷갈림.
- **문제 2** — 자료 검색·PDF 첨부·참고자료 추가 같은 "질문의 사전 세팅" 기능이
  전부 우측 바에 흩어져 있어서, 처음 온 사용자는 **질문 전에 자료를 갖춘다는 개념 자체를 모름.**
- **문제 3** — 좋은 답변은 "좋은 자료 세팅"에서 나오는데, 그 흐름을 UI가 유도하지 못함.

---

## 2. 핵심 컨셉

> **"자료를 갖추고 → 질문 예시로 감을 잡고 → 질문한다."**

웰컴 화면을 위→아래로 재구성 (**초기 세팅 스트립이 예시 카드 위**):

```
┌─────────────────────────────────────────────────────────┐
│                        [ 로고 ]                          │
│                                                          │
│         ─── 질문 전에, 자료를 갖춰보세요 (선택) ───   [접기]│
│      ①  자료 검색       ②  PDF 첨부      ③  추가 설정    │
│    [ 참고자료 검색 ]   [ 파일 첨부 ]    [ 근거·모델 ]     │
│                                                          │
│                  ── 질문 예시 · Suggested ──              │
│        ┌────────┐  ┌────────┐  ┌────────┐               │
│        │ 정의    │  │ 확인    │  │ 애매    │  (예시 카드)  │
│        └────────┘  └────────┘  └────────┘               │
│        ┌────────┐  ┌────────┐  ┌────────┐               │
│        │  …     │  │  …     │  │  …     │               │
│        └────────┘  └────────┘  └────────┘               │
│                                                          │
│   ┌──────────────────────────────────────────────┐      │
│   │  질문을 입력하세요…                     [전송] │      │
│   └──────────────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────┘
```

- **1층 · 초기 세팅 프로세스** (예시 카드 위): 화면 가운데에 **①②③ 큰 버튼** 3개.
  질문하기 전에 자료를 갖추는 흐름을 시각적으로 순서화. 우측에 **[접기]** 토글.
- **2층 · 질문 예시**: 6개 카드 위에 `질문 예시 · Suggested questions` 레이블 → "이건 예시다" 명시.
- **3층 · 질문창**: 하단 고정 (기존).

## 3. 초기 세팅 3단계 (①②③)

| 단계 | 이름 | 동작 | 연결되는 기존 기능 |
|---|---|---|---|
| ① | **자료 검색** | 법령·조례·판례·해석례를 API로 검색해서 이 대화에 추가 | 우측 바 "참고자료 추가" 모달 (`/law-search`, `/law-add`) 재사용 |
| ② | **PDF 첨부** | 사용자 PDF/문서를 첨부(업로드) | chainlit 파일 업로드(클립) + `upload-cache` 파이프라인 |
| ③ | **추가 설정** | 근거 더 찾기 프리셋 + 모델 선택 | `/evidence-search`·`/evidence-context` + `/provider` 재사용 |

### 각 단계 상세

**① 자료 검색**
- 클릭 → 기존 "참고자료 추가" 모달(`#law-search-modal`)이 그대로 뜬다.
- 검색·선택·추가하면 → 모니터링 패널에 "추가" 태그로 누적, 실제 캐싱(사각지대 연동).
- 웰컴 화면에서도 우측 바의 그 기능에 바로 진입하는 큰 입구를 하나 더 놓는 것.

**② PDF 첨부**
- 클릭 → chainlit 기본 파일 첨부 UI를 트리거(클립 버튼 `.click()`).
- 첨부한 문서는 이 대화의 참고자료로 사용.
- (검토) 업로드 캐시(`upload-cache`)와의 관계 — 세션 한정/전역 확인.

**③ 추가 설정 = 근거 더 찾기 프리셋 + 모델 선택**
- **(a) 근거 더 찾기 프리셋** — 질문 전에 미리 판례·해석례(·법령)를 넓게 찾아
  검색 세트에 세팅해 두는 것. 기존 "근거 더 찾기" 모달(`/evidence-search` → 선택 →
  `/evidence-context`)을 **질문 전 단계로 당겨 쓰는** 것.
  - **키워드 소스 = (확정) 사용자가 입력창에 친 질문 초안.** 사용자가 물으려는 내용을
    입력하면, 그 텍스트를 기반으로 **내장 DB(chroma)와 법제처 API 양쪽에서** 관련 근거를
    더 찾아 **검색 세트에 추가**한다. (API 후보 + 로컬 retrieval 후보를 함께 제시)
- **(b) 모델 선택** — provider 선택(`/provider`). 우측 바 모델 버튼과 동일 기능을
  세팅 단계에도 노출.
- 두 기능을 작은 팝오버/모달 하나(`③ 추가 설정`)로 묶어 제시.

## 4. 상호작용 원칙

- **비강제·순차 권유** — ①②③는 전부 선택. 아무것도 안 하고 바로 질문해도 됨.
  "순서대로 갖추면 더 좋다"는 권유이지 강제 아님.
- **익숙해지면 사라지는 튜토리얼** — 사용자가 익숙해지면 안내 없이 바로 질문하는 게 정상 흐름.
  그래서 초기 세팅 스트립은:
  - (i) 시각적으로 가볍게(질문창·카드보다 덜 강조),
  - (ii) **[접기 / 다시 보지 않기]** 토글 제공 → `localStorage`에 기억(`usun_hide_setup`),
  - (iii) 접으면 다음부터 간결한 웰컴(로고 + 예시 카드 + 질문창)만.
- **세팅 상태 배지** — 자료를 하나라도 갖추면 버튼에 개수 배지(예: `자료 검색 · 2`)를 달아
  "지금 이 대화에 무엇이 세팅됐는지"를 첫 화면에서 보여준다.
- **대화 시작 후 = 우측 바로 흡수** — 질문을 보내 웰컴이 사라지면 ①②③ 기능은 우측 바에서
  계속 접근(참고자료 추가/첨부/근거 더 찾기/모델). **웰컴 = 온보딩 입구, 우측 바 = 상시 도구.**

## 5. 구현 관점 메모 (아직 코드 아님)

- 전부 `public/custom.js`의 `buildWelcomeCards()` 확장 + `custom.css` 스타일로 해결.
  백엔드 새 엔드포인트 원칙적으로 불필요(기존 `/law-search`·`/law-add`·`/evidence-*`·`/provider`·업로드 재사용).
- React 트리 밖 body-overlay 방식 유지(기존 `#usun-welcome-cards`) → 크래시 위험 회피.
- ①②③ 버튼은 기존 우측 바 핸들러(`showLawSearchModal()`·`showEvidenceModal()`·모델 토글 등)를
  그대로 호출 → 로직 중복 없음.
- 레이블/①②③/접기 토글은 한 번만 build, childList 변화 최소화 → MutationObserver 루프 방지.
- 접기 상태는 `localStorage`로 부팅 시 즉시 반영.

## 7. 구현 완료 (config ?v=27)

- **프런트 전용** — `public/custom.js` + `custom.css`만. 백엔드 무변경.
- `custom.js`: `renderSetupInto`/`setupStep`(①②③ 스트립), `triggerAttach`(②),
  `showSetupModal`(③ 모델+근거초안), `showEvidenceModal(...,{preset:true})`(질문 전 세팅),
  `refreshSetupBadges`(① 배지), `_toast`(완료 알림). `buildWelcomeCards`에 스트립+예시 라벨 배선.
- **알아둘 점**
  - ③ 근거 검색은 현재 **법제처 API 기반**(`/evidence-search`→`search_laws/precedents/interpretations`).
    "내장 DB 후보 병행"은 후속 과제(§3 (a)). 법령 선택분은 `/law-add`로 실제 캐싱=검색 세트 반영.
  - `/evidence-context`는 단일 blob(다음 질문에 1회 주입) — 프리셋 여러 번이면 마지막이 우선.
    필요 시 누적(append)으로 백엔드 보강 검토.
  - ② 첨부는 chainlit 네이티브 file input 트리거, 못 찾으면 조례 라이브러리 모달로 폴백.
